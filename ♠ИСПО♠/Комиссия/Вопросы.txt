I. Теоретические вопросы (по номерам из файла)
///Вопрос 3. Что такое описатель (handle) объекта и чем он отличается от указателя? Что такое счетчик ссылок?
Описатель (handle) – это абстрактный идентификатор (обычно 32-或 64-битное целое число), который используется операционной системой для ссылки на системный ресурс (файл, процесс, поток, мьютекс, событие и т.д.). В Windows тип HANDLE (void*). Значение handle скрыто от пользователя – это не прямой адрес объекта, а индекс в таблице объектов ядра процесса.

Отличия от указателя:

Указатель содержит реальный адрес памяти и позволяет напрямую читать/писать данные. Handle – это не адрес, его нельзя разыменовать.

Handle используется для взаимодействия с объектом через API-функции (ReadFile, WaitForSingleObject и др.). Указатель позволяет обращаться к памяти напрямую.

Handle обеспечивает уровень абстракции и безопасности: система проверяет права доступа при каждой операции.

Счетчик ссылок (reference count) – это число, показывающее, сколько активных описателей (или ссылок) указывают на один и тот же объект ядра. Когда объект создаётся (CreateFile, CreateMutex и др.), счётчик = 1. При дублировании handle (DuplicateHandle) счётчик увеличивается. При вызове CloseHandle счётчик уменьшается. Когда счётчик достигает 0, объект уничтожается. Это позволяет системе автоматически управлять временем жизни объекта.

///Вопрос 4. Режимы работы ОС (пользовательский, режим ядра). Виды ядер. Что такое системный вызов?
Режимы работы:

Пользовательский режим (user mode) – приложения выполняются с ограниченными привилегиями. Нет прямого доступа к оборудованию, критическим структурам ядра, памяти других процессов. При ошибке (например, обращение к недопустимому адресу) процесс аварийно завершается.

Режим ядра (kernel mode) – код ядра и драйверов имеет полный доступ ко всем ресурсам, памяти, инструкциям процессора. Любая ошибка в этом режиме вызывает крах всей системы (BSOD).

Виды ядер:

Монолитное (monolithic kernel) – вся ОС (управление памятью, процессами, драйверами, файловыми системами) работает в одном адресном пространстве в режиме ядра. Быстро, но ненадёжно (Linux, ранние Unix).

Микроядро (microkernel) – в ядре только минимальные механизмы (IPC, планирование, управление памятью), остальные службы работают в пользовательском режиме. Надёжно, но медленнее из-за частых переключений контекста (QNX, L4).

Гибридное (hybrid kernel) – большинство компонентов в ядре, но некоторые вынесены в пользовательский режим. Компромисс между производительностью и надёжностью (Windows NT, XNU).

Системный вызов (system call) – способ, которым пользовательское приложение запрашивает у ядра выполнение привилегированной операции (открытие файла, создание процесса, выделение памяти). Процесс:

Приложение вызывает функцию WinAPI (например, CreateFile).

Библиотека (kernel32.dll/ntdll.dll) подготавливает параметры и генерирует программное прерывание (int 0x2E) или использует инструкцию sysenter/syscall.

Процессор переключается в режим ядра, передаёт управление диспетчеру системных вызовов.

Ядро проверяет параметры, выполняет запрос, возвращает результат (код ошибки или handle).

Процессор переключается обратно в пользовательский режим.

///Вопрос 6. Какие механизмы синхронизации процессов/потоков вы знаете?
Основные механизмы в Windows:

Критическая секция (CRITICAL_SECTION) – синхронизация между потоками одного процесса. Работает в пользовательском режиме (быстро). При захвате занятой секции поток может уснуть после нескольких попыток (spin count).
Функции: InitializeCriticalSection, EnterCriticalSection, LeaveCriticalSection.

Мьютекс (Mutex) – объект ядра, позволяет синхронизировать потоки как внутри одного процесса, так и между разными процессами (именованный). Имеет счётчик владения (рекурсивный). Может быть использован с WaitForSingleObject.
Функции: CreateMutex, WaitForSingleObject, ReleaseMutex.

Семафор (Semaphore) – объект ядра, позволяющий ограничить количество потоков, одновременно работающих с ресурсом. Счётчик от 0 до максимального значения. Поток уменьшает счётчик при ожидании, увеличивает при освобождении.
Функции: CreateSemaphore, WaitForSingleObject, ReleaseSemaphore.

Событие (Event) – объект ядра, уведомляющий о наступлении некоторого условия. Бывает ручной/автоматический сброс. Используется для оповещения потоков.
Функции: CreateEvent, SetEvent, ResetEvent, WaitForSingleObject.

Атомарные операции – InterlockedIncrement, InterlockedDecrement, InterlockedCompareExchange и др. Работают на уровне процессора без переключения контекста. Используются для простых счётчиков и флагов.

///Вопрос 10. Подсистема управления процессами и потоками. Планирование выполнения.
Подсистема управления процессами и потоками отвечает за создание, удаление, приостановку/возобновление процессов/потоков, а также за распределение процессорного времени между потоками (планирование). В Windows единицей планирования является поток.

Виды планирования:

Долгосрочное (long-term) – решение о том, какой процесс загрузить в память из очереди заданий (в современных ОС почти не используется).

Среднесрочное (medium-term) – свопинг: временная выгрузка процесса на диск для освобождения памяти.

Краткосрочное (short-term) – выбор, какой поток из очереди готовых получит процессор (вызывается каждые ~10-20 мс).

Стратегии планирования:

Вытесняющее (preemptive) – поток может быть принудительно прерван планировщиком по истечении кванта времени или при появлении более приоритетного потока (Windows, Linux).

Невытесняющее (non-preemptive) – поток сам добровольно отдаёт управление (кооперативная многозадачность, использовалась в Windows 3.x).

Алгоритмы планирования:

Round Robin (циклический) – каждый поток получает квант времени (обычно 10-30 мс), по истечении которого уступает место следующему.

Приоритетное планирование – потоки с более высоким приоритетом выполняются раньше. В Windows 32 уровня приоритета (0-31), реального времени 16-31, переменные 1-15.

Многоуровневые очереди (Multilevel Queue) – потоки разделены на классы (интерактивные, фоновые), каждый класс имеет свой алгоритм.

Многоуровневые очереди с обратной связью – приоритет потока может динамически повышаться/понижаться в зависимости от поведения.

Дополнительно (вопросы 1 и 2 – могут быть в билетах)
///Вопрос 1. Системное ПО, интерфейсы.

Системное ПО – операционные системы, драйверы, утилиты (форматирования диска, архиваторы, антивирусы), среды выполнения (Java VM, .NET runtime). Функции: управление ресурсами, обеспечение интерфейса между пользователем/приложениями и оборудованием.

Интерфейс – граница взаимодействия двух компонентов. Виды: аппаратный (порты, шины), программный (API), пользовательский (GUI, CLI), сетевой (протоколы).

///Вопрос 2. Кодировки, кодовая точка, кодовая страница, ANSI vs Unicode.

Кодировка – правило сопоставления символов числам (кодам).

Кодовая точка – уникальный номер символа в стандарте (например, U+0041 = 'A').

Кодовая страница (codepage) – таблица, где 8-битные значения (0-255) сопоставляются символам для определённого языка (CP1251 для кириллицы).

ANSI – устаревший термин для кодовых страниц Windows (1251, 1252). Каждый символ – 1 байт, ограничение 256 символов.

Unicode – универсальный стандарт. В Windows используется UTF-16LE (wchar_t, 2 байта для основных символов, суррогатные пары для редких). Позволяет представить все символы всех письменностей. Отличия: размер символа (1 байт vs 2/4), поддержка языков, совместимость.
